# No comments

1. Define the caller's files or current diff as scope. The parent supplies the named paths or materialized patch.
2. Launch `comment-sicko` through the installed single-child workflow path with a standalone scope brief. Do not ask it to discover changes through Git. Do not restate its rules or select a model.
3. Inspect its report. Reject scope escapes, application-code edits, disproven keep decisions, and unsupported `MUST KILL` claims. Use `how` or `why` when a constraint claim needs evidence.
4. Delete accepted comments. For a flagged code shape, use `architect` once, then apply the smallest in-scope root-cause fix with one writer.
5. For a valid constraint, offer the cheapest type, runtime check, test, or lint encoding. Apply it only within the caller's authority.
6. Report deletions, restored comments, reruns, fixes, encodings, and open constraints.
