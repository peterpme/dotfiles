### Orchestrate

Use this for a standing multi-day program. Use Autonomous run when one session can drive the work to a predicate.

1. Define the countable done predicate, tracks, unit count, wall-clock budget, and merge authority.
2. Create one goal mission. Record standing orders, owner decisions, unit state, next ready action, artifacts, and receipts in mission state or approved durable files.
3. Pilot one unit through brief, fresh worker, verification, fresh review, fix pass, and delivery. Correct the contract before scaling.
4. Use one async `workflowScript` per coordinated wave. Every lane has a stable key, explicit cwd, standalone brief, authority boundary, acceptance checks, and report contract.
5. Keep one writer per checkout. Give parallel writers separate worktrees. Use `scout`, `researcher`, and `reviewer` for parallel reading around the serialized write path.
6. Treat completion delivery as a queue event. Use Fleet status and mission receipts for supervision. Do not poll merely to wait or scrape session files for child results.
7. Land continuously within explicit authority. Receipts and green CI are evidence, not merge authority. Reverify a changed head.
8. On pause or restart, recover with mission list and mission show, then resume the exact next action. Close only after the real predicate passes and every run has a terminal disposition.

At checkpoints, report predicate counts, track state, current delivery frontier, verification receipts, abandoned units, owner decisions, mission id, and durable artifact paths.
