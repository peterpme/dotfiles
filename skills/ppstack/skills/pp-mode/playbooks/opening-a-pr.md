### Opening a PR

Tail of Bug fix and Feature. Not a user-facing match.

1. Work on a branch. Prefer a worktree when a child is writing.
2. Commit in small, ordered commits. Each commit should be able to stand alone.
3. Verify again on the branch you will push.
4. Open a ready PR, not a draft, unless the user asked for a draft.
5. Title: `type(scope): subject`. Description: Why, Scope, Verification. Drop an empty section.

Do not merge unless the user asked.
